# 阶段 3：逐章写作（Chapter Writing）

本阶段目标：依据已确认大纲，按「章节 → 小节 → 段落」逐级扩写，产出连贯、风格统一、深度匹配读者的正文。严禁一次性生成整本书。

## 3.1 写作前置（每次扩写必做）

开始一个单元前，先输出三要素，再生成正文：

- **本部分目标**：这一段/节/章要达成的读者收获。
- **内容结构**：要点清单与展开顺序。
- **写作策略**：采用哪种论证/叙事手法、如何调用阶段 4 风格与阶段 5 增强。

作者可在此处打断调整，再继续。

## 3.2 扩写粒度控制

- 默认按「一章一节一段」推进；每完成一个小节，短暂停顿请作者确认或提出修订。
- 长章可分多次写完，每次在 `00_BOOK_PROJECT.md` 标记进度，避免上下文丢失。
- 作者随时可插入指令：「这段重写」「这里加个案例」「换种说法」——按作者优先原则即时响应。

## 3.3 一致性约束（贯穿写作）

每次生成后执行 `references/07-state-management.md` 的一致性自检：
- 术语与 `TERMS.md` 一致；
- 不重复已完成章节内容；
- 不偏离核心观点；
- 衔接处自然（章首回扣上文，章末铺垫下文）。

## 3.4 风格与增强的注入

- 行文默认套用阶段 4 锁定的文风（见 `references/04-style-system.md`）。
- 专业书自动预埋「理论/框架/案例/步骤/趋势/常见错误」增强块；科普书预埋「类比/故事/简化/趣味案例」（见 `references/05-content-enhancement.md`）。
- 若事实模式为专业/严格，写完一段即按 `references/06-fact-check.md` 给出核查提示，但不阻塞作者继续写作。

## 3.5 输出与落盘

- 正文章节写入 `chapters/<NN>_<slug>.md`。
- 完成后更新 `00_BOOK_PROJECT.md` 进度表（该章 → 已完成），并将新术语、待修订项追加到 `TERMS.md` / `NOTES.md`。
- 向作者交付该章摘要 + 「可继续下一章 / 需修订」提示。
