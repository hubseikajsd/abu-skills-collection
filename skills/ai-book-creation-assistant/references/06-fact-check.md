# 阶段 6：事实验证机制（Fact-Check Modes）

本阶段目标：在作者选定的强度下，对书稿中的事实性内容提供核查与提醒。**作者拥有是否启用及启用强度的决定权；选「关闭」时绝不主动强制验证。**

## 6.1 四档模式（启动时由作者选择，写入状态文件）

| 模式 | 适用 | 行为 |
|---|---|---|
| 关闭 | 小说、创意作品、观点表达 | 按作者创作方向自由书写，AI 不主动核查事实 |
| 基础 | 一般非虚构 | 检查明显事实错误、时间/年份错误、基础逻辑冲突 |
| 专业 | 科普、技术、商业 | 在基础之上，附来源建议、数据核查提醒、专业风险提示 |
| 严格 | 医学、法律、金融、学术研究 | 在专业之上，附引用建议、来源追踪、合规/风险提醒 |

## 6.2 默认协作闭环（基础 / 专业 / 严格 模式通用）

本 Skill 的核查默认是「**AI 先做、作者确认**」，而非「作者先做、AI 复查」。启动阶段即向作者说明此分工，避免把核实负担推给用户。

1. **AI 先核实**：写作中遇到关键事实、数据、年份、制度、人名地名，AI 主动联网检索权威来源（官方史料/档案、学术论文、权威媒体），不等作者发令。
2. **送作者确认**：以「事实核查备忘」逐条呈现「论断 → 拟采用来源 → 置信度」，请作者过目。
3. **作者同意 → 采纳**：作者无异议即把来源回填 `TERMS.md` 来源追踪表，正文保留 `[来源N]` 标记；作者通常只需回「可以 / 继续」。
4. **作者不同意 → 作者自核**：仅当作者质疑某条或想用自有依据时，才由作者自行核实或提供替代出处；AI 不强制、不阻断。

> 前置红线：默认动作是 AI 把查好的结果送到作者面前，而不是让作者去查。

## 6.3 各模式执行流程

### 关闭模式
- 不插入任何核查动作；作者要求时才协助。
- 若作者后续想升级模式，随时可切换并追溯已写章节。

### 基础模式
- 走 6.2 协作闭环：AI 先扫描硬事实（人名/地名/年份/事件顺序）矛盾、明显常识错误、前后逻辑断裂，并直接给出修正建议与依据，再请作者确认。
- 以「一致性备忘」列出疑似问题与可信度，由作者裁定。

### 专业模式
- 走 6.2 协作闭环：AI 先对关键数据/论断检索并附「建议来源」（论文/官方统计/权威媒体），连同数据核查提示、专业风险提示一并送给作者确认。
- 采用的来源回填 `TERMS.md`，正文标 `[来源N]`。

### 严格模式
- 走 6.2 协作闭环：AI 先对重要论断检索并附「引用占位 [来源N]」与来源追踪，强制给出合规/风险提醒（如「此处建议咨询持证专业人士」），送作者确认。
- 不替代专业审查，仅作出版前风控辅助。

## 6.4 输出物

- 核查结果统一写入「一致性备忘 / 事实核查备忘」，不污染正文。
- 专业/严格模式来源追踪表存于 `TERMS.md` 或独立 `SOURCES.md`，随稿交付。
- 所有核查结论标注「AI 辅助检索，已由/待作者确认」，不宣称已确证；最终出处责任在作者。

## 6.5 红线

- 作者选「关闭」后，任何阶段都不得因「觉得该查」而主动阻断写作或强制验证。
- 核查默认由 AI 完成并送确认；**不得把「请你核实来源」设为默认动作推给用户**，仅在作者否决/质疑时才转由作者自核。
- 核查提示不得伪装成既定事实；始终标明不确定性与建议动作。
