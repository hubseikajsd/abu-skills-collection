# Handoff — 会话交接

将当前对话压缩成一份交接文档，让一个全新的 agent 实例（上下文为空）能无缝接续工作。交接文档保留在项目目录下，形成可追溯的交接历史链。交接后主动询问是否生成/更新项目存档报告，供任意 Agent 随时调取复用。

## 何时使用

- 对话过长，AI 开始忘事（重复问过的问题、人名搞混、前后矛盾）
- 完成一个逻辑阶段，想用干净上下文开始下一阶段
- 需要 fork 出一个并行 agent 做另一条线
- 即将接近 token 上限

---

## 两档模式

### 轻量模式（默认）

适用场景：日常交接、换 session 继续、不涉及跨平台。

输出位置：项目目录下的 `handoff/` 子目录，按序号命名。
```
<项目目录>/handoff/handoff-001-<任务名>.md
<项目目录>/handoff/handoff-002-<任务名>.md
...
```

4 段结构：

```markdown
# Handoff #<序号> — <任务名>
> 生成时间：<日期>
> 交接方向：<本 session 做了什么 → 下个 session 该做什么>

## 1. 做了什么
- 已完成的事项（逐条列出，每条带产出物路径）

## 2. 还没做什么
- 清晰的下一步动作指令

## 3. 关键信息（必须原样传递）
- 文件路径、人名/项目名锁定写法、已选定的方案
- 写作类：声线档案、人物表、时间线、文体选择
- 开发类：分支名、技术栈版本、已知 workaround
- 研究类：已搜关键词、信源可信度评估

## 4. 建议的 Skills
- /xxx — 理由
```

### 完整模式（/handoff full）

适用场景：正式阶段切换、跨平台交接（Abu → Codex/ZCode）、需要可追溯的交接记录。

9 字段结构：

```markdown
# Handoff #<序号> — <任务名>
> 生成时间：<日期>
> 交接方向：<本 session 做了什么 → 下个 session 该做什么>

## 1. 目标
一两句话说清整体目标是什么。

## 2. 当前进度
- 已完成的事项（逐条列出，每条带产出物路径）
- 当前停在哪一步

## 3. 关键决策
列出本 session 中做出的重要决策及理由（防止下个 session 推翻重来）。
- 决策1：<决策内容> — 理由：<为什么这么定>
- 决策2：...

## 4. 什么有效
哪些方法/路径被验证可行，值得延续。

## 5. 什么无效
哪些尝试失败了的坑——写了省得下个 session 再踩。
- 失败1：<做法> → 结果：<为什么不work> → 替代方案：<换成了什么>

## 6. 关键状态（必须原样传递）
根据任务类型，以下信息必须逐字保留，不能概括丢失：

### 通用
- 文件路径清单（产出物、素材、配置文件的实际路径）
- 人名/项目名/变量名等专有名词的锁定写法

### 写作类（回忆录/小说/自传）
- 声线档案：传主/角色的口头禅、句式习惯、方言词、视角
- 人物表：所有出现过的角色名字（锁定不动）
- 时间线：已确立的关键日期/事件顺序
- 文体选择：已选定的亚文体（严肃传记/温情回忆录/家族史料/口述整理）

### 开发类
- 分支名、技术栈版本、关键配置
- 已知的 bug 和 workaround

### 研究类
- 已检索过的关键词（避免重复搜）
- 信源可信度评估

## 7. 下一步
清晰的动作指令，下个 session 照着做即可：
- [ ] 步骤1
- [ ] 步骤2

## 8. 建议的 Skills
- /xxx — 理由
- /yyy — 理由

## 9. 敏感信息
已脱敏。如涉及 API Key / 密码 / 个人隐私，此处不写原文，写"已在 <文件路径> 中配置"。
```

## 交接后：项目存档报告

交接文档写完后，**主动询问用户**：

> "交接文档已生成：<路径>
> 是否需要生成/更新项目存档报告？项目存档报告是一份长期保留的 md 文档，放在项目目录下，记录当前项目的完整状态（目标、进度、决策历史、产出物清单），方便任意 Agent 随时调取复用。"

如果用户说需要，就生成或更新项目存档报告并告知路径。如果用户说不需要，就不生成，交接文档已足够。

### 交接文档 vs 项目存档报告

| 维度 | 交接文档 | 项目存档报告 |
|---|---|---|
| 定位 | 某次交接的快照 | 项目全貌 |
| 存放 | `<项目目录>/handoff/handoff-001-xxx.md` | `<项目目录>/PROJECT-STATUS.md` |
| 数量 | 多份，按序号递增 | 一份，持续更新 |
| 读者 | 下一个 session 的 agent | 任意 agent（Abu/Codex/ZCode/Claude.ai） |
| 内容侧重 | 做了什么 → 还没做什么 → 下一步 | 目标、架构、进度看板、决策历史、产出物清单、Agent 复用指引 |
| 更新方式 | 每次重新生成一份 | 增量更新（每次交接后追加新进展、更新进度看板） |
| 生命周期 | 保留不删，形成交接历史链 | 保留不删，随项目持续演进 |

### 项目存档报告结构

```markdown
# 项目存档 — <项目名>

> 最后更新：<日期>
> 当前阶段：<阶段名>
> 最后交接：handoff-003

## 项目概述
目标、范围、当前阶段。

## 进度看板
| 阶段 | 状态 | 产出物 | 备注 |
|---|---|---|---|
| 阶段1 | ✅ 已完成 | <文件路径> | |
| 阶段2 | 🔄 进行中 | | |
| 阶段3 | ⏳ 待开始 | | |

## 关键决策记录
| 日期 | 决策 | 理由 | 影响 |
|---|---|---|---|

## 产出物清单
所有已产出文件的路径和说明。

## 关键状态锁定
（同交接文档的"关键状态"字段，但持续累积，不丢失历史信息）

## 已知问题与规避
踩过的坑，避免重复。

## Agent 复用指引
新 agent 接入本项目时，先读本文件，然后：
1. 读 <产出物清单> 中的文件
2. 执行 <下一步> 中的指令
3. 如需更多上下文，读对应的 handoff 文档
```

## 原则

1. **不编造**——如果某个部分没什么可写的，写"无"，不要编一段听起来合理的内容。一份有幻觉的交接文档比没有更糟糕。
2. **不重复已有文件**——如果信息已经存在于 spec、plan、ADR、issue、commit message、代码注释中，不要复制内容，写路径引用即可。
3. **脱敏**——API Key、密码、个人隐私信息不写入文档，写"已在 xxx 配置"。
4. **原样传递关键状态**——人名、声线档案、时间线等不能概括，必须逐字保留。这是跨 session 一致性的命脉。
5. **裁剪**——如果用户传了 argument-hint（说明下个 session 干什么），据此裁剪文档侧重点，无关信息可省略。
6. **全部保留**——交接文档按序号递增，不覆盖旧的；项目存档报告增量更新，不删历史信息。
